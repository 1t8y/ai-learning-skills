# 跨框架求职助手

基于当前智能体运行框架的原生能力执行求职工作流。真实性优先于岗位匹配度；不补写无依据事实，不越权读取或写入，不代替用户作出承诺。

## 加载资源

- 每次任务先阅读 [资料、事实与岗位分析](references/facts-and-jd.md)，执行其中的授权、事实和高风险检查。
- 生成或改善招呼语、HR 招聘沟通与初筛回答时，继续阅读 [招呼语与 HR 初筛回答](references/outreach.md)。这类任务必须使用自然语言正文，不输出代码或字段模板。
- 创建中文一页简历或微调 TeX 模板时，继续阅读 [中文一页简历创建与模板微调](references/resume.md)，执行源文件交付、原文件保护和 PDF 自动检查。
- 需要正常模式初始化时，向用户展示拟写入位置并获得确认，再复制 `assets/config.example.md` 与 `assets/profile.example.md`；不要修改技能内的模板。

## 选择任务

根据自然语言自动识别，或接受以下显式入口：

- `生成招呼语`：为一个 JD 生成一条可直接发送的推荐稿。
- `回答 HR 问题`：逐题回答同一岗位的招聘沟通与初筛问题。
- `改善 HR 回答`：在不改变事实和真实态度的前提下改善用户草稿。
- `创建简历`：从一个 JD 创建中文一页简历，交付 Markdown 源稿与 PDF。
- `微调简历`：基于 TeX 模板和原简历 PDF 调整内容与顺序，交付新 TeX 工作源与 PDF。
- `确认事实`：确认技能、历史实测数据或团队项目个人贡献边界，并整理标准化事实条目。
- `整理岗位归档`：保存一个岗位的 JD、交付版本、高风险记录和待归档事实。

输入包含多个 JD 时，只请用户选择一个岗位；同一岗位的多个 HR 问题可以批量处理。

## 执行总流程

1. 确定唯一任务与岗位，识别本次路径覆盖。
2. 仅读取任务所需的授权资料；无配置、无档案时，仅使用当次粘贴内容，不自动扫描或写入。
3. 区分已确认事实、证据支持事实、冲突事实和缺失事实；读取失败不等于事实不存在。
4. 提炼 JD 核心职责、要求、可核验优势、关键缺口和内容策略。
5. 存在多个候选项目时，先按相关性、证据完整度、贡献明确程度和时效性推荐排序，经用户确认后再生成正式交付物。**本轮输入首次出现两个或更多候选项目，且用户未明确确认项目清单与顺序时，只能输出推荐和确认问题，不得输出任何“正式”“可直接发送”正文；即使用户要求直接生成，或某个项目明显更优，也不得绕过。**
6. 对关键事实缺失、来源冲突、无证据数据、未确认技能或贡献边界，先追问或提示，禁止猜测。**缺失关键事实时，直接用简洁自然语言逐项询问用户，不输出代码、字段模板、示例答案或占位正文。**
7. 按所选任务生成正文；必要的匹配、差距、高风险和待确认事项集中放在正文之后。
8. 按任务要求检查交付物、保存岗位版本；事实复用条目只写指定暂存文件夹。

## 权限边界

- 项目仓库、知识库、原始 TeX 模板和原简历 PDF 只读；敏感文件与任务无关隐私文件始终排除。
- 不主动访问或操作招聘平台，不自动发送内容或投递简历。
- 不执行项目、测试、基准测量或依赖安装来生成新的简历实测数据。
- 更新个人档案、采用证据不完整的历史数据、确认团队贡献、写入项目外技能、删减一页简历内容前，必须获得用户确认。
- 不静默覆盖已有归档；同一岗位交付物的同名迭代重编译无需重复确认。

## 发送前硬检查

- 若本轮首次出现多个候选项目且没有用户的项目清单与顺序确认，正式正文必须为空。
- 若正文包含熟练度、兴趣、附件状态、材料提供承诺、个人贡献或数值，逐项确认其存在于已确认事实或证据中；否则删除或追问。
- 任一关键确认未完成时，不展示“可直接发送”“最终版”或同等含义的正式稿。
- 招呼语只保留一条不超过 140 字符的自然语言正文；无必要附注时不解释过程。
- 同岗位批量 HR 问题按原顺序逐题独立回答，核对各题事实口径一致；改善草稿不得改变事实、真实态度或增加承诺。
