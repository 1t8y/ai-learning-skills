# 代码编写/修改阶段工作流

## 第 1 步：每次变更后 AI 必须写「变更说明」

AI 每次写完或改完代码，必须在回复中包含：

```
本次改动：
1. 新增/修改了哪个文件或函数，这个文件/函数的功能是什么
2. 关键函数的输入是什么、输出是什么
3. 我怎么验证它工作了（给一条具体命令）
```

用户不需要看懂每一行代码，但 AI 必须保证用户能看懂「这个改动干了啥、怎么验证」。AI 给出验证命令后，等待用户跑通并确认，这一步才算完成。

## 第 2 步：AI 写的代码必须带中文注释

AI 输出的所有代码遵守：
- 每个文件顶部用 3 行中文说明这个文件是干嘛的
- 每个函数顶部用 1 行说明输入参数和返回值

示例：
```python
# 文件：extract.py
# 功能：从 PDF 文件中提取纯文本内容
# 输入：PDF 文件路径，输出：提取后的文本字符串

def extract_text(pdf_path: str) -> str:
    """输入 PDF 文件路径，返回提取的纯文本字符串"""
    ...
```

## 第 3 步：AI 维护 PROJECT_MAP.md 项目地图

项目根目录必须维护一个 **`PROJECT_MAP.md`** 文件。每次项目结构发生变化（新增文件、删除文件、模块重组）时，AI 必须主动更新该文件：

1. 在 `PROJECT_MAP.md` 中**追加**最新版本的项目地图（带日期），禁止覆盖删除历史版本
2. 每个版本标注本次相比上一版新增/修改/删除了什么
3. 地图中每个文件/目录用一句话说明功能

格式示例：

```markdown
# 项目地图

## 2026-09-11（当前版本）
```
my-project/
├── main.py            ← 程序入口
├── core/
│   ├── extract.py     ← PDF 文字提取
│   └── summarize.py   ← 生成摘要（新增）
└── config/
    └── settings.py    ← 配置文件
```
> 本次变化：新增 summarize.py，负责摘要生成

## 2026-09-10（上一版本）
```
my-project/
├── main.py            ← 程序入口
├── core/
│   └── extract.py     ← PDF 文字提取
└── config/
    └── settings.py    ← 配置文件
```
```

如果项目中还没有 `PROJECT_MAP.md`，AI 在第一次结构变更时主动创建。这样用户随时能看到项目是怎么一步步长大的，改哪个功能要动哪个文件也一目了然。
