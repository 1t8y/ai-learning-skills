# 报错排查阶段工作流

## 核心原则

AI 收到报错信息后，禁止直接给出修复代码。必须先从报错中提取关键信息、确认上下文，然后用大白话解释原因，最后才给修复方案。

## 第 1 步：AI 主动提取报错关键信息

AI 收到报错后，首先自己从报错信息中提取以下内容（不需要用户先做）：

1. **错误类型和位置**——读报错最后一行，通常写了错误类型和文件行号，例如：
   `File "main.py", line 123, in extract: ModuleNotFoundError: No module named 'pdfplumber'`

2. **错误关键词判断**——根据报错中的关键词判断大致类型：
   - `Timeout` / `timed out` → 超时，网络或响应太慢
   - `Permission` / `Access denied` → 权限不够
   - `ModuleNotFound` / `ImportError` → 缺依赖包，没安装
   - `SyntaxError` → 代码语法写错了
   - `KeyError` / `IndexError` → 字典或数组访问了不存在的键/下标
   - `Connection` / `404` / `500` → 网络请求或 API 出问题

3. **追问缺失的上下文**——如果用户只贴了报错没说在做什么，AI 必须主动问：
   - 「你运行的是什么命令？」
   - 「报错之前改了哪个文件？」
   禁止在缺少上下文的情况下直接给修复方案。

## 第 2 步：AI 先用大白话解释原因

AI 必须先向用户解释：
- 这个错误是什么意思（用大白话，不用专业术语）
- 大概率是哪一步出了问题、为什么会出问题
- 如果有多种可能原因，列出最可能的 1-2 种，不要一次给 5 种方案让用户试

## 第 3 步：AI 再给修复方案和代码

解释完原因后，AI 才给出：
1. 修复方案说明：要改哪个文件、改什么、为什么这么改
2. 具体代码（如果需要改代码）

## 第 4 步：AI 给出验证命令，等待用户确认

修复后，AI 必须给出验证命令，等待用户跑通并确认错误消失后，才算修复完成。如果修复后出现新错误，AI 重新从第 1 步开始排查。

## 常见错误速查表（AI 参考用）

| 关键词 | 大白话解释 | 通常解决办法 |
|--------|-----------|-------------|
| ModuleNotFoundError | Python 找不到这个库 | 用 pip 或 uv 安装缺失的包 |
| PermissionError | 没有权限读写文件或端口 | 换个目录、用管理员权限、或换个端口号 |
| TimeoutError | 等太久没响应 | 检查网络、增加超时时间、或确认目标服务是否启动 |
| SyntaxError | 代码格式写错了 | 看报错行号，检查括号、引号、缩进是否配对 |
| KeyError | 字典里没有这个键 | 打印字典内容看看实际有哪些键 |
| ConnectionRefused | 连不上目标服务 | 确认服务启动了、端口号对不对 |
